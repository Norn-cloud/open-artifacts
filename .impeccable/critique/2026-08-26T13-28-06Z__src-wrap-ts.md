### Design Specificity Verdict

- **LLM assessment**: The viewer chrome and container are exceptionally grounded in Open Artifacts' product truth — "The Quiet Instrument". The recent sheet container introduction transforms raw HTML documents into curated, tactile artifacts while strictly respecting the flat chrome doctrine and preserving the infinite spatial plane for canvas-mode artifacts.
- **Deterministic scan**: 15 advisory design-system findings on `src/wrap.ts`, located exclusively in legacy unlock shell and status page templates (e.g. font sizes `2rem`, `1.15rem`, `3px` radius). 0 violations in the newly added sheet container implementation.
- **Visual evidence**: Inset 12px sheet with 8px radius on dark `#232329` / light `#f2f2f2` backdrop; sticky headers reliably re-pinned to sheet inner edge; canvas mode cleanly opts out to full-bleed.

### Overall Impression
The viewer chrome achieves Figma/Linear-grade tool restraint. The sheet container successfully solves the "unfinished raw HTML" problem without compromising mobile responsiveness, handoff coordinate fidelity, or canvas spatial freedom.

### What's Working
1. **The Inset Sheet Container**: Gives artifacts breathing room and clear visual identity without decorative drop-shadow bloat.
2. **Deterministic Canvas Mode Bypass**: Zero-config runtime detection preserves full-bleed infinite canvas workflows.
3. **Strict Flat Depth Model**: Border hairlines and surface lightness staircases provide crisp separation across light and dark themes.

### Priority Issues

- **[P2] Unlock Shell Token Alignment**
  - **Why it matters**: The client-side password decrypt form (`unlockShell`) uses ad-hoc font sizes (`2rem`, `1.15rem`, `.625rem`) and radii (`3px`, `12px`) that drift from the core 4-8px design system.
  - **Fix**: Realign unlock card, typography, and buttons with standard `--oa-*` tokens.
  - **Suggested command**: `$impeccable polish src/wrap.ts`

- **[P2] Frame Paint Transition**
  - **Why it matters**: On slow network or large document loads, the iframe can pop in abruptly once parsed.
  - **Fix**: Add a lightweight opacity transition (`opacity: 0 -> 1` over `150ms`) on iframe load event.
  - **Suggested command**: `$impeccable polish src/wrap.ts`

- **[P3] Comments Drawer Draft Protection**
  - **Why it matters**: Pressing `Escape` while typing a comment immediately closes the drawer and discards draft input.
  - **Fix**: Prevent immediate close if the textarea has unsubmitted text, or preserve draft in a temporary variable.
  - **Suggested command**: `$impeccable harden src/wrap.ts`

### Persona Red Flags
- **Alex (Power User)**: Cannot press `c` to open comments or `t` to toggle theme from document focus; must tab to header controls.
- **Jordan (First-Timer)**: Encrypted password unlock page feels visually disconnected from the sleek artifact viewer.
- **Sam (Accessibility User)**: All header controls provide excellent `:focus-visible` rings and ARIA attributes; touch targets strictly meet 28px+ with `-6px` hit-area expansion.

### Minor Observations
- Comment timestamp strings could use `tabular-nums` styling for consistency.
- Status page action buttons could adopt the pill radius (`999px`) used by the sign-in chip.

### Questions to Consider
- Should we expose optional global keyboard shortcuts (`c` for comments, `t` for theme) in the host shell?
- Should the password unlock card share the exact same sheet/card tokens as the comments drawer?
