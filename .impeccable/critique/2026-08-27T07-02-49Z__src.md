## Design Specificity Verdict

This chrome is unmistakably authored for this product. The --oa-* token bridge, the sheet-on-backdrop framing, the live-agent presence semantics, and the handoff dock's state machine are tied to product-specific concepts. A generic SaaS could not drop this chrome in unchanged.

Deterministic scan: 4 advisory findings in src/handoff/styles.ts, 0 in public/index.html. Three are false positives documented in DESIGN.md (2px micro-radius, 7rem countdown). One is potentially actionable: #000 on camera video element (line 86).

## What's Working

1. The --oa-* bridge makes "chrome follows the artifact" a real invariant.
2. The repeating ghost icon-button is consistency as identity.
3. Sheet-on-backdrop framing is the right metaphor, executed well.

## Priority Issues

### [P0] Invisible keyboard layer contradicts "keyboard is first-class"
- Why: c/t shortcuts have no aria-keyshortcuts, no tooltips, no help overlay. Dock actions have no shortcuts at all.
- Fix: Add aria-keyshortcuts, lightweight tooltips, extend shortcuts to dock actions, add ?-triggered shortcut sheet.

### [P1] High-stakes irreversible actions lack confirmation
- Why: Visibility to Public applies on select change with no confirm. Comment delete is one click. Handoff Discard is immediate.
- Fix: Gate visibility-to-public and handoff Discard behind confirm popover. Add undo window on comment delete via toast.

### [P1] Dead-link / error states are terminal and cold
- Why: Artifact not found offers one muted line + go home link, no recovery guidance. Decrypt error is a bare danger alert.
- Fix: Add actionable guidance line, copy URL affordance, reframe decrypt error as "That password didn't work — try again."

### [P2] No loading affordance inside the sheet during slow artifact load
- Why: Frame is opacity:0 until data-ready. On slow connections the sheet looks blank.
- Fix: Quiet centered spinner or "Loading artifact..." caption on the backdrop, cleared on data-ready.

### [P2] Icon-only toggles have no visible labels or tooltips for sighted users
- Why: First-timers can't identify live/handoff/comments/filter without clicking.
- Fix: Add restrained native title tooltips or tiny custom tooltip on hover/focus-visible.
